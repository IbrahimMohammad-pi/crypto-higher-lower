# Product Requirements Document: Higher or Lower Crypto Challenge

## 1. Overview

### Project Description
Higher or Lower Crypto Challenge is a multiplayer web game that leverages SNAK and Starknet to create an engaging blockchain-integrated gaming experience. Players compete to correctly identify which of two presented cryptocurrencies has the higher current market price. The game requires each player to deposit a token stake, with the winner of 5 rounds collecting both stakes and any additional in-game rewards.

This MVP aims to deliver a simple yet engaging game that effectively demonstrates the integration of SNAK for blockchain interactions (including token transfers and Binance MCP-powered price fetching).

### Hackathon Criteria
This project emphasizes SNAK and Starknet usage as a core judging criterion. The implementation must showcase effective use of SNAK's capabilities for token transfers and price data retrieval, demonstrating meaningful integration with the Starknet blockchain ecosystem.

## 2. Scope of Integration

### Primary Functions
- **Token Stakes**: Players must stake tokens to participate in the game, managed through SNAK's token transfer capabilities.
- **Token Swaps**: The game will facilitate token swaps as needed for gameplay mechanics.
- **Real-time Price Data**: Integration with SNAK's Binance MCP functionality to fetch current prices for a variety of cryptocurrencies (ETH, BTC, SOL, AVAX, etc.).
- **Point Calculation**: Points awarded based on both correctness and speed of player responses.

### Fallback Strategy
The application architecture must implement a separation of concerns that ensures the core game logic and non-blockchain elements continue to function if SNAK components fail or become unresponsive. This includes implementing timeouts, fallback states, and graceful degradation of blockchain-dependent features.

## 3. System Architecture

### High-Level Architecture

The system will consist of the following components:
- **Frontend**: Modern React-based web application with WebSocket support for real-time gameplay.
- **Backend**: Python-based API server handling game logic, player sessions, and scoring.
- **SNAK Integration Layer**: Dedicated Node.js/TypeScript service that wraps SNAK functionality (token transfers, price fetching) and isolates blockchain interactions.
- **Smart Contracts**: Cairo contracts deployed on Starknet to handle token stakes and game rewards.

The architecture will implement a fallback mechanism ensuring the main application logic remains decoupled from SNAK-dependent components, allowing the game to continue functioning in a limited capacity even if blockchain interactions fail.

## 4. Integration Details

### SNAK Integration Layer (Node.js Wrapper Service)

#### Setup Process
1. **SNAK Submodule**: Ensure the SNAK repository is cloned as a submodule in the `snak/` directory.
   ```bash
   git submodule update --init --recursive
   ```
2. **SNAK Dependencies**: Install SNAK's own dependencies (likely using `pnpm install` within the `snak/` directory, refer to SNAK's README).
3. **Wrapper Service Setup**: Inside `snak-integration/`:
   - Initialize a Node.js project (`npm init -y` or `yarn init -y`).
   - Install necessary dependencies: `express`, `typescript`, `@types/node`, `@types/express`, potentially `ts-node`, `nodemon` for development.
   - Configure `tsconfig.json`.

#### Integration Approach: API Wrapper Service
1. Create an Express.js (or potentially leverage SNAK's NestJS structure if feasible via direct import) service within `snak-integration/src/server.ts`.
2. This service will import necessary functions/modules directly from the *sibling* `../snak/` directory (adjusting paths and potentially needing TypeScript path mapping in `tsconfig.json`).
3. **Endpoints**: Expose simple HTTP endpoints:
   - `/transfer`: Handles requests from the Python backend to initiate token transfers using SNAK functions.
   - `/price`: Handles requests to fetch token prices using SNAK's Binance MCP integration.
   - `/health`: Basic health check.

```typescript

app.use(express.json());

app.post('/transfer', async (req: Request, res: Response) => {
  try {
    const { from, to, amount, token } = req.body;
    // Validate input
    const result = await transferTokenFunction(/* args */);
    res.status(200).json({ status: 'success', data: result });
  } catch (error: any) { // Add basic error handling
    console.error("SNAK Transfer Error:", error.message);
    res.status(500).json({ status: 'error', message: 'SNAK transfer failed' });
  }
});

app.get('/price/:symbol', async (req: Request, res: Response) => {
  try {
    const { symbol } = req.params;
    // Validate input
    const price = await getPriceFunction(symbol);
    res.status(200).json({ status: 'success', data: { symbol, price } });
  } catch (error: any) {
    console.error("SNAK Price Error:", error.message);
    res.status(500).json({ status: 'error', message: 'Failed to get price via SNAK' });
  }
});

// Health check, etc.

app.listen(PORT, () => {
  console.log(`SNAK Integration Service running on port ${PORT}`);
});
```

**Isolation**: This wrapper service isolates the main Python backend from the complexities and direct dependencies of the SNAK Node.js project. The backend only needs to make simple HTTP calls.

## 6. MVP Game Mechanics & Blockchain MVP

### Game Flow
1. Player creates or joins a game room (via Python backend).
2. Both players deposit token stakes (frontend -> Python backend -> **Node.js SNAK Wrapper**).
3. Game consists of 5 rounds.
4. Each round:
   - Python backend requests two random crypto symbols.
   - Python backend calls **Node.js SNAK Wrapper** `/price/:symbol` endpoint for both symbols.
   - Backend sends symbols (without prices) to frontend via WebSocket.
   - Players select the higher-priced coin.
   - Backend evaluates answers based on prices fetched via SNAK wrapper, calculates points.
   - Backend sends round results via WebSocket.
5. After 5 rounds, winner determined by Python backend.
6. Stakes transferred to winner (Python backend -> **Node.js SNAK Wrapper**).

### Fallback Mechanism
If the SNAK Integration Layer service is unresponsive or returns errors:
- Price fetching: Backend uses cached/stale prices or informs players.
- Token transfers: Backend triggers fallback (virtual stakes, retry later) and notifies players.

### Minimum Features
- Wallet connection.
- Token staking and transfer via SNAK wrapper service.
- Real-time crypto price comparisons fetched via SNAK wrapper service.
- 5-round gameplay loop.
- Winner determination and stake distribution via SNAK wrapper.

## 7. Testing, Deployment, and Security

### Testing Requirements
- **SNAK Integration Service**: Unit tests for wrapper logic, integration tests calling actual SNAK submodule functions (mocked or on testnet), endpoint tests.
- **Python Backend**: Unit tests for business logic, integration tests mocking calls to the SNAK wrapper service, tests for fallback logic.
- **Frontend**: Component tests, E2E tests covering game flow.

### Deployment Considerations
- **SNAK Integration Service**: Deploy as a separate Node.js service (e.g., Docker container, serverless function). Requires access to the SNAK submodule code during build/runtime.
- **Backend**: Deploy Python FastAPI service. Needs the URL of the SNAK Integration Service configured.
- **Frontend**: Deploy static build to Vercel.
- **Configuration**: Environment variables for SNAK wrapper URL, Python backend URL, contract addresses, network details, API keys.

### Security Considerations
- Secure communication between Backend and SNAK Integration Service (e.g., network policies, potentially API keys if deployed publicly).
- Input validation at both the Python backend and the SNAK Integration Service layer.
- Protect SNAK's sensitive configurations (private keys, etc.) - should be managed by the SNAK Integration Service, not exposed to the Python backend.

## 8. Monitoring and Maintenance

### Logging and Analytics
- Log requests/responses between Python backend and SNAK Integration Service.
- SNAK Integration Service should log interactions with the SNAK submodule and any errors.
- Monitor health and performance of both services.

### Ongoing Maintenance
- Keep SNAK submodule updated.
- Update SNAK Integration Service accordingly if SNAK's internal APIs change.
- Monitor dependencies for security vulnerabilities in all services.
